# 21.异常处理

## 异常处理

写代码的时候，我们总希望程序能按照我们的想法一直跑下去。但现实是：程序运行时总会遇到各种意外，比如把一个字符串转成整数、拿 0 去做除法、访问列表中不存在的元素……Python 遇到这些情况时会怎么做？它会**抛出（raise）一个异常**，然后程序就中断了。

这一讲我们专门学习 Python 的**异常处理机制**，它的作用是：**让程序遇到意外时不要"当场崩溃"，而是优雅地处理掉，然后继续往下跑**。

> **课时安排**：课时三学习"异常处理基础"（什么是异常、`try...except`、`else`、`finally`），课时四学习"异常处理进阶"（`raise`、自定义异常、断言、实战与规范）。

### 什么是异常

我们先来看一段"会出问题"的代码，代码如下所示。

```python
print(10 / 0)
```

运行上面的代码，程序会立刻中断，屏幕上会出现这样一段信息：

```text
Traceback (most recent call last):
  File "demo.py", line 1, in <module>
    print(10 / 0)
ZeroDivisionError: division by zero
```

这段信息叫做**调用栈追踪（Traceback）**，它告诉我们三件事：程序在哪里出的问题（第几行）、是什么问题（`ZeroDivisionError`）、问题的说明是什么（`division by zero`，即"除数为零"）。

Python 把这类"运行时错误"统一称为**异常**（exception），每一种异常都有自己对应的类型。常见的异常类型如下表所示。

|异常类型|说明|典型例子|
| ---------------------- | ---------------------- | ---------------------- |
|`ZeroDivisionError`|除数为零|`10 / 0`|
|`ValueError`|值不合法|`int('abc')`|
|`TypeError`|类型不对|`'a' + 1`|
|`NameError`|使用了不存在的名字|`print(undefined_name)`|
|`IndexError`|下标越界|`[1, 2, 3][10]`|
|`KeyError`|字典中不存在的键|`d['x']`|
|`AttributeError`|对象没有这个属性|`'abc'.uppercase()`|
|`FileNotFoundError`|文件不存在|`open('不存在.txt')`|

既然异常会让程序中断，那么我们的目标就是：**让程序遇到意外时不要"当场崩溃"，而是优雅地处理它，然后继续往下跑**。这就要用到 Python 的异常处理机制。

### try...except

Python中和异常相关的关键字有五个，分别是`try`、`except`、`else`、`finally`和`raise`，我们先看看下面的代码，再来为大家介绍这些关键字的用法。

```python
try:
    # 可能出错的代码写在 try 代码块中
    print(10 / 0)
except ZeroDivisionError:
    # 如果出现了 ZeroDivisionError，就执行这里的代码
    print('除数不能为 0')
```

运行上面的代码，输出如下所示。

```
除数不能为 0
```

这就是最基本的异常处理：**把可能出错的代码放进`try`代码块，把出错了怎么办的代码放进`except`代码块**。当`try`中的代码正常执行时，`except`中的代码会被跳过；当`try`中的代码抛出异常时，程序会到`except`中去找匹配的异常类型，找到就执行对应的处理代码，程序不会中断。

一个`try`后面可以跟上一个或多个`except`块，分别处理不同的异常，代码如下所示。

```python
num = input('请输入一个整数：')
try:
    num = int(num)
    print(100 / num)
except ValueError:
    print('您输入的不是合法的整数')
except ZeroDivisionError:
    print('除数不能为 0')
```

如果希望在处理异常时**同时拿到异常的具体信息**，可以在`except`后面加上`as 变量名`，代码如下所示。

```python
try:
    print(10 / 0)
except ZeroDivisionError as e:
    print('出错了：', e)
```

输出：

```
出错了： division by zero
```

我们也可以用一个`except`同时捕获多种异常，这时需要把异常类型写成元组，代码如下所示。

```python
try:
    num = int(input('请输入一个整数：'))
    print(100 / num)
except (ValueError, ZeroDivisionError) as e:
    print('输入的数据有问题：', e)
```

如果希望**无论发生什么异常都能接住**，可以捕获`Exception`类（它是绝大多数常规异常的父类），代码如下所示。

```python
try:
    print(10 / 0)
except Exception as e:
    print('程序出错了：', e)
```

> **注意**：上面这种"什么都接住"的写法虽然方便，但会把代码中的真实错误一起隐藏掉，导致问题难以排查。实际开发中请尽量捕获**具体**的异常类型；只有在确实需要"无论如何都要兜住"的场合（比如服务器长期运行的程序）才考虑捕获`Exception`。

### else和finally

`try`代码块除了可以跟`except`，还可以跟`else`和`finally`代码块。

- `else`代码块中的代码**只有在`try`中没有发生异常时才会执行**；
- `finally`代码块中的代码**无论有没有发生异常都会执行**，所以它被称为"总是执行代码块"，最适合用来做释放外部资源之类的收尾工作。

我们用一段代码把三个关键字的效果都体现出来，代码如下所示。

```python
num = input('请输入一个整数：')
try:
    num = int(num)
    print(100 / num)
except ValueError:
    print('您输入的不是合法的整数')
except ZeroDivisionError:
    print('除数不能为 0')
else:
    print('一切正常，结果是：', 100 / num)
finally:
    print('本次计算结束')
```

运行上面的代码（输入 20），输出如下所示。

```
一切正常，结果是： 5.0
本次计算结束
```

如果把上面代码中输入的内容改成`abc`，输出则是：

```
您输入的不是合法的整数
本次计算结束
```

可以看到，`else`部分的代码在发生异常时并没有执行，而`finally`部分的代码两种情况下都执行了。

`finally`最大的用途是**释放资源**，比如关闭文件、释放锁。另外还有一条重要的注意事项：**不要在`finally`代码块中写`return`语句**，否则会把`try`中原本要抛出的异常"吃掉"，让程序以为一切正常。

### raise

前面我们一直在"处理"别人抛出的异常，其实我们也可以**主动抛出异常**。

在 Python 中，可以使用`raise`关键字来引发异常，当函数收到的参数不合法时，用抛出异常的方式告知调用者问题出在哪里，代码如下所示。

```python
def check_age(age):
    """检查年龄是否合法"""
    if age < 0:
        raise ValueError('年龄不能为负数')
    if age > 150:
        raise ValueError('年龄太大了，请确认输入')
    return age


print(check_age(20))   # 20
print(check_age(-1))   # ValueError: 年龄不能为负数
```

> **说明**：上面代码的第二行会打印出一段 Traceback，这**不是代码写错了**，而是因为我们没有捕获这个异常——异常一旦抛出又没人接住，程序就只能中断了。

这里的思路是：**函数只负责"检查"，发现输入不合法就抛异常，具体怎么应对由调用者决定**。调用者如果希望程序遇到非法输入就直接结束，那么不捕获这个异常即可；如果希望给出友好的提示，就用`try...except`接住它，代码如下所示。

```python
try:
    age = int(input('请输入您的年龄：'))
    print(check_age(age))
except ValueError as e:
    print('输入有误：', e)
```

### 自定义异常类型

Python 内置的异常类型已经能满足大部分需求，如果我们需要表达更具体的业务含义，还可以定义自己的异常类型。

自定义异常类型的规则很简单：**写一个类，继承`Exception`（或者某个内置异常类）即可**。代码如下所示。

```python
class ScoreError(Exception):
    """自定义的成绩异常类型"""
    pass


def check_score(score):
    """检查成绩是否合法"""
    if not 0 <= score <= 100:
        raise ScoreError('成绩必须在 0~100 之间')
    return score


print(check_score(90))   # 90
print(check_score(120))  # ScoreError: 成绩必须在 0~100 之间
```

> **说明**：类的定义语法我们在《面向对象编程》一章会详细介绍，这里先了解"自定义异常 = 继承 Exception 的一个类"即可。如果希望自己的异常也能被`except ValueError`这样的代码捕获，把`Exception`换成`ValueError`就可以了。

### 断言

除了主动抛出异常，Python 还提供了一个专门用来做"内部检查"的语句——**断言**（assert）。

断言的语法非常简单：`assert 条件, '断言失败时的提示信息'`。当条件为真（True）时，程序什么都不做，继续往下执行；当条件为假（False）时，Python 会抛出一个`AssertionError`异常，程序就此中断。

我们先来看一个例子，代码如下所示。

```python
def check_age(age):
    """检查年龄是否合法"""
    assert 0 <= age <= 150, '年龄必须在 0~150 之间'
    return age


print(check_age(20))   # 20
print(check_age(200))  # AssertionError: 年龄必须在 0~150 之间
```

可以看到，断言失败时抛出的异常类型是`AssertionError`，它同样是`Exception`的子类，因此我们也可以用`try...except`接住它，代码如下所示。

```python
try:
    age = int(input('请输入您的年龄：'))
    print(check_age(age))
except AssertionError as e:
    print('输入有误：', e)
```

#### 断言和raise有什么区别

这两者看起来很像，都是"条件不满足就报错"，但用途完全不同。

|对比项|`assert`断言|`raise`主动抛出|
| ---------------------- | ---------------------- | ---------------------- |
|检查的对象|程序内部的"不应该发生"的情况|需要通知给调用者的错误|
|面向的对象|程序员自己|调用者（用户或其他代码）|
|典型场景|函数的前置条件、算法的前提假设|用户输入非法、参数不合法|
|能否被关闭|能，用`python -O`启动时断言不执行|不能|

下面两个函数实现的功能完全一样，但表达的意思不同。第一个函数里的断言是"写给程序员自己看的"——在调用方已经检查过输入的前提下，`scores`一定是个非空列表，这条断言平时不会被触发，它只是防止将来有人改动代码时破坏了这个前提。

```python
def average(scores):
    """计算平均分（断言版）"""
    assert len(scores) > 0, '成绩列表不能为空'
    return sum(scores) / len(scores)
```

第二个函数才是真正把错误"抛给调用者"，让调用者能够给出友好的提示。

```python
def average(scores):
    """计算平均分（异常版）"""
    if not scores:
        raise ValueError('成绩列表不能为空')
    return sum(scores) / len(scores)
```

**使用断言的三条注意事项**：

1. **断言是"保险丝"而不是"校验"**：它用来检查程序内部的不变量，不要拿它校验用户输入——用户输入是不可控的外部数据，应该用`if`加`raise`来处理；
2. **不要在断言中写有副作用的表达式**：因为断言可能被禁用，里面的副作用就不会发生；
3. **断言是可以被关闭的**：用`python -O`（优化模式）启动程序时，所有断言都不会执行，所以关键的业务逻辑不要写在断言里。

我们用上面的`average`函数做一次对比实验就很清楚了。正常启动时，传入空列表会得到一条清晰的`AssertionError`：

```
AssertionError: 成绩列表不能为空
```

而用`python -O`启动时，断言被跳过，程序会一路算下去，最终抛出让人一头雾水的`ZeroDivisionError`（除数为零）：

```
ZeroDivisionError: division by zero
```

这正是"关键逻辑不能写在断言里"的原因——断言一旦被关掉，它保护的东西就没人管了。

> **说明**：Python 在启动时如果带上`-O`参数，`__debug__`的值会变成`False`，我们也可以借助它来判断当前是否处于优化模式。

### 异常处理实战

下面我们把前面学到的知识组合起来，写一个"成绩录入"的小程序：不断提示用户输入成绩，直到输入合法为止，代码如下所示。

```python
class ScoreError(Exception):
    """自定义的成绩异常类型"""
    pass


def input_score():
    """录入一个成绩并返回它，录入不合法就一直提示"""
    while True:
        try:
            score = int(input('请输入成绩（0~100）：'))
            if not 0 <= score <= 100:
                # 成绩不合法，主动抛出自定义异常
                raise ScoreError('成绩必须在 0~100 之间')
            return score
        except ScoreError as e:
            print('输入有误：', e)
        except ValueError:
            print('请输入一个整数！')


score = input_score()
print('录入成功，成绩是：', score)
```

我们来分析一下上面的代码。

- `try`中先把输入转换成整数，如果用户输入了`abc`，`int()`会抛出`ValueError`，被下面的`except ValueError`接住；
- 转换成功后检查成绩范围，如果不在 0~100 之间，就用`raise`抛出自定义的`ScoreError`；
- `except ScoreError as e`负责接住成绩不合法的情况，打印提示后`while True`继续下一轮循环；
- 直到用户输入了合法成绩，函数才`return`结束。

再看一个"菜单选择"的例子，这是我们在《分支和循环结构》一章中写过的猜数字游戏的改进版，代码如下所示。

```python
import random


def guess_number():
    """猜数字小游戏"""
    answer = random.randint(1, 100)
    print('我已经想好了一个 1~100 之间的整数，来猜猜看！')
    while True:
        try:
            guess = int(input('请输入你猜的数字：'))
        except ValueError:
            print('请输入一个整数！')
            continue
        if guess < answer:
            print('猜小了，再试试。')
        elif guess > answer:
            print('猜大了，再试试。')
        else:
            print('恭喜你，猜对了！')
            return


guess_number()
```

上面的代码中，输入不合法时用`continue`跳过本轮循环，让用户重新输入；输入合法之后，再进行大小比较。

### 异常处理小结

|关键字|作用|
| ---------------------- | ---------------------- |
|`try`|放置可能出现异常的代码|
|`except`|捕获异常并进行处理，可以写多个，也可以用`as`获取异常信息|
|`else`|`try`中没有发生异常时才执行|
|`finally`|无论是否发生异常都会执行，适合做释放资源的收尾工作|
|`raise`|主动抛出异常，常用于参数校验|
|`assert`|断言，条件不成立时抛出`AssertionError`，常用于检查程序内部的前提|

**使用异常处理的几条原则**：

1. **不要用异常机制处理正常业务逻辑或控制程序流程**，简单的说就是不要滥用异常机制，这是初学者常犯的错误；
2. **尽量捕获具体的异常类型**，不要动不动就`except Exception`，否则会掩盖代码中的真实错误；
3. **捕获异常后不要"装作没看见"**，至少要给出提示信息或记录日志，否则问题会被悄悄吞掉；
4. **不要在`finally`中写`return`**，否则会吞掉原本要抛出的异常；
5. **异常信息要写得有意义**，例如`raise ValueError('年龄不能为负数')`比`raise ValueError('error')`要有用得多。

### 知识点总结

本讲我们学习了 Python 的异常处理机制，目标是让程序在遇到意外时不至于"当场崩溃"。

- **概念**：**异常**是程序运行时出现的错误，Python 会抛出异常并给出 Traceback；异常处理机制由`try`、`except`、`else`、`finally`和`raise`五个关键字组成；**断言**（`assert`）是条件不成立时抛出`AssertionError`的语句，用来检查程序内部的前提；**自定义异常**就是继承`Exception`（或某个内置异常类）写出来的类。
- **操作方法**：把可能出错的代码放进`try`，用`except`捕获并处理（可以写多个，也可以用`except ... as e`拿到异常信息，用元组一次捕获多种异常）；`else`仅在没有异常时执行，`finally`始终执行，适合释放资源；用`raise`主动抛出异常；用`assert 条件, '提示'`做内部检查。
- **代码要点**：捕获异常时尽量写具体的异常类型；`AssertionError`同样能被`except`捕获；`finally`中不要写`return`，否则会吞掉异常；异常信息要写得能说明问题，例如`raise ValueError('年龄不能为负数')`。
- **命名规则**：自定义异常类名以`Error`结尾（如`ScoreError`），一眼就能看出它是一个异常类型；函数名要能体现"检查什么"，如`check_age`、`check_score`。
- **注意事项**：不要用异常机制来处理正常业务逻辑或控制程序流程；不要动不动就捕获`Exception`，否则会掩盖代码中的真实错误；捕获后不要"装作没看见"；**断言只用来检查程序内部的前提，不要用它校验用户输入**，而且它会被`python -O`关闭，关键业务逻辑不能写在断言里。
- **学习重点**：能独立写出一个包含`try...except...else...finally`的完整异常处理结构，并能说清楚每一部分什么时候执行；会用`raise`为函数做参数校验、知道`assert`与`raise`的区别；能自己定义一个异常类型并正确地抛出和捕获它。
